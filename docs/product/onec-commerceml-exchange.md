# Обмен с сайтом (CommerceML) — подключение УТ 11

Канал, в котором **1С сама шлёт данные на сайт**. Это штатный «Обмен с сайтом»
типовых конфигураций (УТ 11, Розница, Бухгалтерия) — **доработка конфигурации
не нужна**, всё настраивается в пользовательском режиме.

Второй канал (сайт сам ходит в HTTP-сервис 1С) описан в
[onec-http-contract.md](./onec-http-contract.md) и остаётся для тех, у кого
сервис уже написан.

---

## Что происходит

1. Продавец в кабинете (**Профиль → 1С**) выбирает канал «1С сама шлёт на сайт»
   и жмёт «Сгенерировать логин и пароль».
2. Эти логин, пароль и адрес обмена он вбивает в узел обмена своей 1С.
3. По расписанию 1С выгружает `import.xml` (каталог) и `offers.xml` / `prices.xml`
   / `rests.xml` (цены и остатки), а сайт отдаёт ей новые заказы.
4. Продавец в кабинете сопоставляет группы номенклатуры 1С с категориями сайта.
   **Пока группа не сопоставлена, её товары на витрину не попадают.**
5. Новые карточки уходят на модерацию. Цены и остатки у уже одобренных
   обновляются сразу, без повторной проверки.

---

## Шаг 1. Кабинет на сайте

1. Профиль → **1С**.
2. Канал: **«1С сама шлёт на сайт (CommerceML)»**.
3. **«Сгенерировать логин и пароль»** — пароль показывается **один раз**,
   скопируйте его сразу. Забыли — перевыпустите, старый перестанет работать.
4. Отметьте «Обмен включён» → **Сохранить**.

Со страницы понадобятся три значения: **адрес обмена**, **логин**, **пароль**.

---

## Шаг 2. Узел обмена в УТ 11

В пользовательском режиме (не в конфигураторе):

1. **НСИ и администрирование → Интеграция с другими программами**
   (в 11.4 — «Администрирование → Синхронизация данных»).
2. Включить флажок **«Обмен с сайтом»**.
3. **«Настройки обмена с сайтом»** → создать узел:
   - **Адрес сайта** — адрес обмена со страницы кабинета
     (например `https://gitorg.ru/onec/exchange`);
   - **Пользователь** / **Пароль** — выданные на сайте;
   - **«Проверить подключение»** — должно ответить успешно.
4. На закладке **«Выгрузка товаров»**:
   - выбрать **вид цены** (одну; какие именно попадут на витрину, ещё раз
     отмечается на сайте);
   - выбрать **склады**, чьи остатки выгружать;
   - включить **«Выгружать картинки»**;
   - задать расписание. **Реже одного раза в 10 минут** — чаще сайт ответит
     `failure` с просьбой увеличить интервал.
5. На закладке **«Обмен заказами»** включить загрузку заказов с сайта.

> **Важно:** первая выгрузка должна быть **полной**, не «только изменения» —
> иначе на сайте не появится дерево групп, и сопоставлять будет нечего.

---

## Шаг 3. Сопоставление категорий

После первой выгрузки в кабинете (Профиль → 1С) появится таблица
**«Категории 1С → категории сайта»**.

- Выбирается **конечная подкатегория** дерева сайта (лист), не промежуточный узел.
- Подгруппы **наследуют** категорию родителя, если у них не задана своя —
  сопоставлять каждый лист номенклатуры не нужно.
- «Сохранить сопоставления» перевешивает уже импортированные карточки сразу,
  дожидаться следующего обмена не нужно.

Товары появятся на витрине после ближайшей выгрузки цен и остатков — доступность
пересчитывается там же, где приходит `Количество`.

## Локальный тест с 1С на том же ПК

1С и сервер на одной машине — самый простой стенд, туннель не нужен.

```bash
npm --prefix server run start:dev
```

В узле обмена 1С указать адрес `http://localhost:4444/onec/exchange`
(порт — из `PORT` в `server/.env`).

Проверка протокола без 1С — эмулятор всего цикла:

```bash
npm --prefix server run onec:commerceml-smoke
```

## Протокол (что именно происходит по HTTP)

Сайт слушает один эндпоинт `GET|POST /onec/exchange`, ветвление по `?type=&mode=`.

### Каталог (`type=catalog`)

| Шаг | Запрос | Ответ сайта |
| --- | --- | --- |
| 1 | `GET ?mode=checkauth` + Basic auth | `success\n<имя cookie>\n<значение>` |
| 2 | `GET ?mode=init` | `zip=yes\nfile_limit=8388608` |
| 3 | `POST ?mode=file&filename=…` (тело — байты) | `success` |
| 4 | `GET ?mode=import&filename=…` | `success` |

Файл больше `file_limit` 1С досылает кусками с тем же `filename` — сайт
склеивает их append'ом. `mode=import` ставит разбор в очередь и отвечает сразу:
каталог на десятки тысяч позиций разбирается минутами, 1С столько не ждёт.

### Заказы (`type=sale`)

| Шаг | Запрос | Ответ сайта |
| --- | --- | --- |
| 1 | `GET ?mode=checkauth` + Basic auth | `success\n…` |
| 2 | `GET ?mode=init` | `zip=…\nfile_limit=…` |
| 3 | `GET ?mode=query` | XML CommerceML с новыми заказами |
| 4 | `GET ?mode=success` | `success` |

Заказ считается переданным **только после `mode=success`** — оборванный обмен
не теряет заказ, он придёт в следующий раз.

Все ответы идут с HTTP 200, включая отказы: 1С читает первую строку тела
(`success` / `failure` / `progress`), а не код ответа.

## Что сайт делает с данными

| Из 1С | Куда на сайте |
| --- | --- |
| `Товар/Ид` (или `Ид#ИдХарактеристики`) | `Product.product1cGuid` |
| `Артикул` | `productArticle` |
| `Наименование`, `Описание` | `productName`, `productDescription` |
| `Группы/Ид` | `product1cGroupId` → категория по сопоставлению |
| `Картинка` из `import_files/` | S3, с дедупликацией по MD5 |
| `ЗначенияСвойств`, `ЗначенияРеквизитов` | `productCharacteristics` |
| `Цена/ЦенаЗаЕдиницу` выбранного типа | `productPrice` |
| `Склад/КоличествоНаСкладе` выбранных складов | `productStockQuantity` |
| `Статус="Удален"` | снятие с витрины |

**Частичные обновления.** `prices.xml` и `rests.xml` — тот же
`ПакетПредложений`, просто с разным наполнением. Нет `<Цены>` — цена не
трогается, нет остатка — не трогается остаток.

**Полная vs частичная выгрузка.** После полной (`СодержитТолькоИзменения="false"`)
всё, чего не было в файле, снимается с витрины. После частичной — нет.

## Ограничения и лимиты

| Что | Значение | Переменная окружения |
| --- | --- | --- |
| Кусок файла | 8 МБ | `ONEC_EXCHANGE_FILE_CHUNK_LIMIT_BYTES` |
| Один файл после склейки | 512 МБ | `ONEC_EXCHANGE_MAX_FILE_BYTES` |
| Вся сессия обмена | 2 ГБ | `ONEC_EXCHANGE_MAX_SESSION_BYTES` |
| Стартов обмена на логин | 6 / 10 мин | — |
| Неудачных авторизаций с IP | 60 / 10 мин | — |
| Запросов внутри сессии | 600 / мин | — |
| Время жизни сессии | 6 ч | — |
| Временная папка обмена | `%TEMP%/izibuy-1c-exchange` | `ONEC_EXCHANGE_TMP_DIR` |

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `failure Неверный логин или пароль обмена` | Перевыпустите пароль в кабинете и вставьте заново |
| `failure Интеграция с 1С выключена` | Не стоит галочка «Обмен включён» |
| `failure В кабинете выбран другой канал обмена` | Канал стоит на «сайт ходит в 1С» — переключите на CommerceML |
| `failure Слишком частый обмен` | Расписание в 1С чаще, чем раз в 10 минут |
| Товары импортировались, но их нет в каталоге | Группа не сопоставлена — таблица категорий в кабинете |
| Товары есть, но цена 0 и «нет в наличии» | Дошёл только `import.xml`; ждём `offers`/`prices`/`rests` |
| В журнале «Укажите адрес самовывоза в профиле» | У продавца в профиле нет адреса с координатами |
| Цена не та | На сайте отмечен не тот тип цены (блок «Что выгружать на витрину») |
| Остаток больше ожидаемого | Отмечено несколько складов — остатки суммируются |

Журнал приёмки — в кабинете, блок **«Приёмка файлов из 1С»**: там видно, что
именно прислали, что создалось и какие позиции не прошли.
