# Подключение УТ 11 к Izibuy — канал «сайт ходит в 1С»

> **Скорее всего, вам нужен не этот документ.** Здесь описан канал, требующий
> написать HTTP-сервис в конфигурации. В типовой УТ 11 то же самое делается
> галочками через штатный «Обмен с сайтом» — см.
> [onec-commerceml-exchange.md](./onec-commerceml-exchange.md).
>
> Этот путь имеет смысл, только если HTTP-сервис у вас уже написан.

Цель: чтобы сайт мог спрашивать у вашей 1С товары и присылать заказы.

Вам нужно сделать **три вещи**:

1. В 1С — маленький **HTTP-сервис** по [контракту](./onec-http-contract.md).
2. **Опубликовать** его так, чтобы был адрес вида `https://…` (или `http://…` в локальной сети).
3. В кабинете сайта вставить этот адрес и **API-ключ**.

Если с конфигуратором незнакомы — отдайте программисту 1С:

1. [Чеклист программиста](./onec-ut11-programmer-checklist.md) ← **главный документ для него**
2. [Контракт JSON](./onec-http-contract.md)

Разовая работа.

---

## Что у вас уже есть (по вашим ответам)

- ПК подключается к **облачному серверу** 1С  
- База скорее **клиент-сервер**, сервер почти всегда включён  
- Конфигурация — **обычная (типовая) УТ 11**  
- HTTP-сервис раньше **не публиковали** — это нормально, сделаем впервые  

---

## Шаг 0. Пока без «настоящей» публикации

На своём ПК можно отладить сайт с **mock**:

```bash
cd server
npm run onec:mock
```

В кабинете:
- URL: `http://127.0.0.1:3091`
- ключ: `mock-onec-key`

Так проверяется весь путь на сайте без правки 1С.

---

## Шаг 1. HTTP-сервис в конфигурации УТ 11

В конфигураторе (кратко для программиста 1С):

1. Добавить **HTTP-сервис** (например `IzibuyExchange`).
2. Корневой URL шаблона — например `izibuy`.
3. Методы:
   - `GET …/v1/health`
   - `GET …/v1/nomenclature` — выборка номенклатуры + цена + свободный остаток
   - `POST …/v1/customer-orders` — создать **Заказ покупателя**, идемпотентно по `externalId`
4. Проверка `Authorization: Bearer <ключ>` (ключ храните у себя, тот же вставите на сайте).
5. Ответ — JSON как в контракте.

> Имена объектов УТ («Заказ покупателя», справочник «Номенклатура») остаются внутри 1С. Наружу — только поля контракта.

## Шаг 2. Публикация на веб-сервере

Нужен адрес, по которому **наш сервер сайта** (или ваш ПК при локальном тесте) достучится до сервиса.

Типовой путь 1С:

1. «Администрирование» → публикация на веб-сервере (IIS / Apache — как принято у вашего хостера облака).
2. Включить HTTP-сервисы.
3. Получить URL вида:  
   `https://ваш-сервер/имя_публикации/hs/izibuy`  
   (точный хвост зависит от имени HTTP-сервиса и шаблона).

Проверка в браузере/Postman:

```http
GET https://…/v1/health
Authorization: Bearer ваш-ключ
```

Должен вернуться JSON с `"ok": true`.

Если облачный хостер 1С **не даёт** внешний HTTP — пишите хостеру «нужна публикация HTTP-сервиса» или временно тестируйте через туннель (ngrok и т.п.) только для разработки.

---

## Шаг 3. Кабинет на сайте

1. Войти → **Профиль → 1С**  
2. Вставить URL и ключ  
3. Включить «Обмен включён» → **Сохранить**  
4. **Проверить соединение**  
5. **Обменять сейчас** — появятся товары  
6. Сделать тестовый заказ на сайте — в 1С должен появиться заказ покупателя (после sync / в течение ~5 мин)

Смотрите **журнал обмена** на той же странице — там текст ошибки, если что-то не так.

---

## Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| Таймаут / connection refused | URL недоступен с сервера сайта; firewall; публикация |
| 401 | Неверный Bearer-ключ |
| Товары не появляются | Пустой `items` или нет `guid`/`name`/`price` |
| Заказ не уходит | У товара на сайте нет `product1cGuid` (не из sync) |
| «Нельзя создать товар вручную» | Так и задумано при включённой 1С |
