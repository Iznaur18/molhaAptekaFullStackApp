# Связка клиента с сервером — что сделано и с чего начать

Этот текст для тех, кто первый раз подключает фронт к своему API.

## Зачем это вообще нужно

Браузер открывает страницу с одного адреса (например `http://127.0.0.1:5173` — это Vite).  
API живёт на другом порту (`http://127.0.0.1:4444` — Express).  
Для браузера это **два разных сайта**. Если просто написать полный URL API в `fetch`, сервер должен явно разрешить такие запросы (CORS). Плюс в production адрес API часто другой.

Чтобы в **разработке** не упираться в CORS и не хардкодить порт в каждом запросе, в проекте настроен **прокси Vite**.

## Что именно добавлено в проект

### 1. Прокси в `vite.config.js`

Все запросы из браузера, которые идут на **тот же хост**, что и страница (у нас `127.0.0.1:5173`), по путям:

`/auth`, `/user`, `/vote`, `/order`, `/product`, `/uploads`, `/upload`

…Vite **перенаправляет** на бэкенд `http://127.0.0.1:4444` с тем же путём.

То есть в коде ты пишешь, например:

```js
fetch('/auth/login', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ email, password }) })
```

Браузер шлёт запрос на `127.0.0.1:5173/auth/login`, Vite тихо проксирует его на `127.0.0.1:4444/auth/login`. Для браузера это «свой» сайт — **CORS к API не нужен** в этом режиме.

Важно: в конфиге клиента и прокси используется **`127.0.0.1`**, не `localhost`. Для браузера `localhost` и `127.0.0.1` — **разные origin**; если смешать, появятся странные ошибки CORS.

### 2. Константа `API_BASE_URL` в `src/shared/config/apiBaseUrl.js`

- В **разработке** (`npm run dev`) с прокси значение пустое: в `fetch` используются пути `/auth/...`.
- В **production** в `.env` задаётся `VITE_API_URL` (см. `client/.env.example`) — тогда к URL добавляется этот префикс.

Пример:

```js
import { API_BASE_URL } from './shared/config/apiBaseUrl'

const res = await fetch(`${API_BASE_URL}/auth/login`, { ... })
```

### 3. Подсказка на сервере в `server/.env.example`

Для случая, когда фронт ходит на API **напрямую** с другого origin (без прокси), на сервере нужен `FRONTEND_URL` с точным URL страницы, например `http://127.0.0.1:5173`. В примере `.env` это расписано.

### 4. `client/.env.example` и `.gitignore`

Шаблон для `VITE_API_URL` при сборке; файл `.env` в клиенте в `.gitignore`, чтобы секреты не попали в git.

## Что сделать тебе руками

1. Запустить **MongoDB** и сервер из папки `server` (как в `server/docs` / `npm run start:dev`).
2. В `server/.env` при прямых запросах с браузера на порт 4444 указать `FRONTEND_URL=http://127.0.0.1:5173`.
3. Запустить клиент: в папке `client` — `npm run dev`.
4. В коде вызывать API как `${API_BASE_URL}/auth/...` (или просто `/auth/...`, если `API_BASE_URL` пустой).

После этого первый осмысленный шаг в коде — например, форма логина с `POST /auth/login` по документации в `server/docs`.
